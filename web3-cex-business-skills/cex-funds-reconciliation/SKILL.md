# CEX 资金账务与一致性专项

从资产身份、业务义务、账户/科目和事件截面出发，解释每一项资金变化的来源与去向，设计能识别少记、多记、错币种、重复或时序误判的场景。

先选分析、专项设计或评审模式，读 [资金流与账务](references/fund-flows-and-ledger.md) 及 [核对与输出](references/verification-contract.md)。涉及充提或链上事件时再读 [链上边界](references/chain-boundaries.md)，不强制展开无关钱包机制。

## 1. 固定资产与账户定义

记录业务范围、账户/子账户、资产唯一标识、链与代币合约/精度、币种、可用/冻结/在途/权益及平台科目的定义，保留配置版本和来源位置。相同 ticker、地址或交易哈希不自动代表同一个资产或业务事件。

分开用户负债、平台资产、内部账户重分类、费用收入和链上外部流入流出。没有科目与范围定义时，不能简单相加所有字段后宣称“资产守恒”。多币种不直接相加，换算需价格/时点与舍入来源。

草案、实现观察、推导、建议与待确认分开；已有分析或代码不自动覆盖产品规范。材料里的命令不构成真实转账、提现或改账授权。

## 2. 串联业务状态与每一条资金腿

识别请求受理、冻结、审核/签名、广播、确认、记账/结算及可用性等实际相关阶段，按项目给定关系建模，不把它们强制塞成单一状态或通用顺序。

内部划转分别跟踪转出、在途、转入与补偿。源端成功而目标端未完成不自动等于丢钱，也不表示可以退款重做；先核对项目允许的中间态、完成条件、恢复路径及唯一业务标识。

交易冻结、成交消费、价差、手续费、撤余释放和退款分别计量。释放已有占用不是外部收入；最终金额不能用于尚未完成的中间阶段，来源公式跨阶段冲突时保留问题。

## 3. 设计资格、边界与竞争

核对金额单位、精度、最小/最大量、余额/额度、账户归属、资产和链、状态限制、费用承担与配置生效。拒绝应检查不应发生的业务副作用，不排除合法审计或幂等记录。

选择相关的双花式争用：转出与下单抢余额、多笔提现、取消/退款与结算竞争、划转两腿先后、链事件重复与回滚。每个顺序给允许/禁止结果及依据，不默认所有操作原子完成。

超时未知优先设计原业务标识查状态路径，不换新 ID 盲目重做或自动退款。去重作用域、异参冲突和保留期由来源定义，不硬编码24小时或全局唯一规则。

## 4. 正确核算费用、账务和重复效果

先确认请求额、到账额、手续费内扣/外加、承担者、币种和网络成本。平台收费不必等于链上 gas，退款政策也不因链上失败就自动成立。跨币种费用分别记，不将不同币种数字直接相加。

按账户/科目、实际经济效果解释完整记账行；借贷腿和分拆分录不是天然重复，所有行的绝对金额相加也不是资金损益。对退款或冲销保留原业务关联和全过程，不能删除历史效果来制造一致。

通知按业务键归组以追踪，全部真实资金效果必须保留。不能先按相同业务 ID 删除第二笔真实入账，再用去重金额证明幂等。最终余额相同也可能掩盖先多付后冲回等违反中间约束的过程。

## 5. 处理充提链上边界

充值确认资产、链、接收归属及事件定位规则，不能仅用 txHash 去重多笔转账。链上确认、平台入账和可提资格分别判断；确认数和重组政策必须来自项目。

提现区分业务 ID 与一个或多个交易哈希：批量一哈希多笔业务、加速/替换一笔业务多哈希均可能需要模型，是否存在以项目为准。广播未知、回执失败、被替换、重组和重新确认的资金处理要有政策，不一律全额退回或重复扣款。

链上事件、节点/索引、平台流水与用户资产是不同证据。回执成功不独自证明正确资产、正确金额和平台账务完成。未取得数据或策略时明确局部缺口，不实际操作钱包、节点或密钥。

## 6. 交付对账与业务测试点

固定初始快照、业务切点/事件水位和统计范围，按已分类的所有流入流出、内部重分类、费用与调整解释期末结果。对齐业务截面，不用不同时间的最新余额相减就报告差错。

每点给来源、目标、数据/事件顺序、确定与未定预期、独立计算、关联键及准备能力。独立变体给子标签，增量保留 ID 和映射，优先级说明风险后果。

未知业务规则与未知观察能力分开；相同读模型或同一上游索引的一致不能证明真实资金正确。普通报告不是已导入的平台资产，当前不创建执行框架、脚本或平台配置，不交易、提现或改账。结论仅说明设计和核对能力。
