# 资金流、费用与账务

## 先定核对范围

逐资产、逐账户和科目确认可用、冻结、在途、钱包/权益的定义，说明哪些是明细、哪些是汇总，不能把包含关系的字段相加。平台资产和用户负债不在同一侧，不能为满足一个总和等式随意抵消。

内部转移可能改变可用和占用而不改变钱包；手续费可能从用户转到平台收入；网络费用可能是另一资产的外部流出。先分类再计算。

## 主要业务场景

| 链路 | 核对维度与风险 |
|---|---|
| 内部划转 | 源端/在途/目标腿、同一业务标识、异步中间态、同键重复/异参、失败恢复、补偿与入账竞争 |
| 冻结与消费 | 请求与真实成交、剩余占用、费用预留、部分成交、撤改单、价差及最终释放；每个截面公式有适用范围 |
| 费用 | 内扣或外加、收付币种、承担者、maker/taker或会员等级、折扣/返佣、配置版本与逐笔/累计舍入 |
| 退款/冲销 | 原始义务、已付/在途/待退、网络费用与平台收费是否退、部分退、重复退款及原操作晚成功 |
| 余额竞争 | 多笔转出或与交易抢可用、检查到扣款之间的旧快照、负余额与信用权限的明确例外 |
| 结算/对账 | 按业务切点关联订单、成交、资金腿与流水，未决业务单列，差额定位到事件和阶段 |

所有条件都需项目来源。没有保留期、错误码或补偿时限时只给问题，不用通用默认值补空。

## 账务腿和经济效果

先解释每条记录的账户、资产、科目、方向、金额、阶段及与原业务的关系。复式记账借贷两行、分批入账或多行费用分配可能组成一次合法效果，不能按行数或相同业务 ID 判重复。

反之，相同 ID 也不能成为删除真实重复效果的理由。保留全部记录，按语义核算实际效果，结合期初/期末快照核对。通知去重用于消费或关联的约定，不能在测试核对阶段把错误多付的一笔删掉。

冲销和修正应按项目规则保留可追溯关系。净额恢复不一定消除过程中违反余额、重复出款或可提限制的错误；是否允许某类中间态需规范。

## 在途与补偿

如果源端已扣、目标未入，先核对在途科目或明确待结义务，不能把该截面当最终丢失；但也不能允许永久在途。完成条件、超时与恢复规则分开，未给业务时限时不造值。

重试应沿同一已确认业务身份查状态。补偿与晚到原操作竞争时，区分未提交、已提交未知、部分完成，避免“既退款又入账”。选择幂等键或事务实现是研发决策，本 Skill 不指定架构。

## 费用与金额核算

固定计费基数、费率单位、内扣/外加、资产、账户承担者、精度与舍入时点。手续费表变更要确认旧业务是锁定创建配置还是使用执行配置。

逐笔舍入后求和与总额计算后一次舍入可能不同，不能自行选择看起来更接近的数。链上实际成本、平台对用户收费和对做市/代理分摊是不同量；差异不自动等于账务错误。

小额显示为0不证明最小单位余额为0；负值或尾差需要按存储单位和政策检查。所有资金计算用 Decimal 或最小单位整数。
