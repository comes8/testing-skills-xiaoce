# 只减仓需求分析与评审

本报告基于合成资料。**准备程度：可部分继续。** 单向持仓、逐仓、USDT 结算线性永续、普通限价单和“只减仓且不反向开仓”的目标已明示，可以继续设计基础数量模型和明确主链路的验证。执行时竞争、超额委托处理及账务核算仍缺规则，相关终态和金额预期暂不能固定。本结论不是实现验证或发版批准。

## 1. 来源与本次范围

| 来源 | 性质与位置 | 本次使用的依据 |
|---|---|---|
| SRC-A | 产品需求草案 v0.3，第 2 章；案例 01 第 11–15 行 | 产品与模式、`reduceOnly=true` 目标、5 张减 2 张的例子、展示、数量单位及公式缺口 |
| SRC-B | 研发方案草案 v0.2，第 3 章；第 19–23 行 | 拟议接入参数、下单时可平校验、送撮合、仓位与账务两个消费者和查询拆分，以及尚未讨论的机制 |
| SRC-C | 交互说明草案 v0.1，第 1 章；第 27–28 行 | 无仓位时禁用按钮；存在其他平仓入口但关系未定义 |

三份材料均为草案；没有已批准规则、真实接口、源代码、存储结构或运行证据。下面对 SRC-B 的描述是“方案明示”，不是“实现观察”。本次不扩展全仓、双向持仓、反向合约或其他订单产品，也不假设止盈止损、强平等具体入口已经存在。其他平仓入口只按 SRC-C 已确认的能力类别核对与本次委托的竞争。

目标变化是为普通限价减仓单引入 `reduceOnly=true`，使用者通过订单入口提交后，应能查询委托及成交，并在仓位、账务处理后核对结果。当前材料没有规定 `reduceOnly=false` 或省略该参数时是否改变旧行为，这属于兼容核对，不能自行扩写成新规则。

## 2. 已知规则与可继续设计部分

| ID | 规则及适用条件 | 证据状态与来源 | 设计可用性 |
|---|---|---|---|
| RUL-001 | 本次只覆盖 USDT 结算的线性永续，单向持仓、逐仓账户、普通限价减仓单；数量为张 | 材料明示，SRC-A，第 11–12、15 行，草案 | 已限定合法分析范围；张的最小步长仍缺失 |
| RUL-002 | `reduceOnly=true` 的业务结果只能减少当前方向的仓位，不能因该委托产生反向仓位 | 材料明示，SRC-A，第 12 行，草案 | 可作为不反向的目标不变量；不据此擅定超额委托应裁剪还是取消 |
| RUL-003 | 初始多仓 5 张，委托全部成交 2 张，且无其他仓位事件时，结果为多仓 3 张 | 材料明示，SRC-A，第 13 行，草案 | 可以核对这个明确例子的数量结果；不能据此推出费用或保证金金额 |
| RUL-004 | 下单成功后展示当前委托；成交后展示历史委托及成交记录 | 材料明示，SRC-A，第 14 行，草案 | 可以检查明示的展示；部分成交仍挂单和部分成交后撤单的展示关系待补充 |
| RUL-005 | 无仓位时页面禁用减仓按钮 | 材料明示，SRC-C，第 27 行，草案 | 可以设计页面校验；不能代替服务端对直接请求的处理规则 |

可继续的主路径：在符合项目最终输入约束的初始多仓 5 张条件下，提交有效的只减仓限价委托；当其成交 2 张且无其他仓位事件时，累计成交为 2 张，仓位为多仓 3 张，并按资料展示委托和成交记录。此处不补入具体价格、数量步长或费用。

## 3. 链路、研发影响和风险

拟议链路为：接入层接收参数 → 订单服务读取仓位及校验 → 送撮合 → 成交事件分别由仓位、账务消费者处理 → 订单、仓位、余额查询及页面展示。此链路来自 SRC-B；具体接口名、数据表、队列和部署组件均未提供。

| ID | 影响对象与资料依据 | 需要研发核对的变化及业务后果 |
|---|---|---|
| IMP-001 | 入口及下单校验；SRC-B 第 19–20 行，SRC-C 第 27 行 | 定义方向与当前仓位的映射、无仓位/不合适方向/非法数量的服务端结果。仅禁用页面按钮不能覆盖直接请求和页面状态过期 |
| IMP-002 | 校验到撮合执行之间的仓位竞争；SRC-B 第 20、22–23 行，SRC-C 第 28 行 | 下单读取仓位后，其他入口或另一委托可能先减仓。只在提交时检查不足以从方案上证明不会超平或反向；需要说明执行裁决点及一致性保证，不能自行认定一定使用锁或特定存储 |
| IMP-003 | 仓位和账务两个消费者；SRC-B 第 21–22 行 | 单边处理、重复/乱序事件和重启可能造成仓位与资金截面不同或重复副作用。需定义关联标识、每个消费者的去重范围、处理完成标记、补偿/重放边界及最终收敛规则 |
| IMP-004 | 订单、仓位、余额查询及展示；SRC-A 第 14 行，SRC-B 第 21 行 | 受理、成交、订单终态和账务完成的语义及观察时点未定义。三个查询一致不能自动证明账务正确，需要关联成交和流水核对 |
| IMP-005 | 参数引入与在途委托；SRC-A 第 12 行，SRC-B 第 19 行 | 核对未传参数、旧客户端/旧委托如何解释及何时适用新规则；无资料时不宣布需要迁移或修改既有数据 |

以上是待核实风险，不是已复现缺陷。

## 4. 集中待确认问题

| ID / 严重程度 | 位置与具体缺口 | 风险、需决策事项及受阻范围 |
|---|---|---|
| ISS-001 / 阻塞性（局部） | SRC-A 第 12 行，SRC-B 第 20、22–23 行，SRC-C 第 28 行：未定义可平数量是否扣除已挂减仓量，以及实际执行前仓位变化的处理 | 两笔委托各自通过同一仓位快照，或其他平仓先发生，可能使剩余委托超过实际仓位。产品/风控与研发需决定可平分配、执行时复核与仲裁保证；超额部分可取消、裁剪或采取其他符合目标的处理，但不能在本分析中选定。阻塞多单竞争、挂单后仓位减少/归零及超额分支的接受结果、订单终态和占用释放；不阻塞 RUL-003 的限定例子 |
| ISS-002 / 阻塞性（局部） | SRC-B 第 19–20 行，SRC-C 第 27 行：无仓位直接下单、方向不匹配、数量零/负数、数量步长及超出可平量时的返回和副作用未写明 | 页面禁用不能保证服务端行为。需明确合法输入、校验时点、拒绝或其他处理方式，以及是否创建业务订单/资金占用。无仓位或错误方向不得通过成交产生新方向仓位，这是 RUL-002 的目标；具体响应和终态仍待定。阻塞输入边界和拒绝分支，不能把审计记录也一概禁止 |
| ISS-003 / 重要 | SRC-B 第 19、22 行：`clientOrderId` 已接收，但没有业务唯一性、重试和未知结果语义 | 提交已生效而响应丢失时，盲目重试可能产生第二笔委托。需明确标识作用域、保留周期、同标识异参处理、按何标识查询及未知状态恢复路径。阻塞超时重试的订单次数及终态预期；不因缺资料宣称已重复下单 |
| ISS-004 / 重要 | SRC-B 第 21–22 行：两个消费者的顺序、去重和恢复未定义 | 同一成交重复消费可能重复减仓或重复结算；一个消费者完成、另一个失败时可能查询到不同截面。研发需说明稳定成交关联标识（字段待提供）、各消费者副作用去重和恢复证据、乱序处理、重放与账务完成的判断；产品与研发明确允许的中间态和收敛时限。阻塞异常、恢复和异步一致性验收，不编造毫秒目标 |
| ISS-005 / 阻塞性（仅金额） | SRC-A 第 15 行：缺合约乘数、费用、保证金释放公式及相关精度 | 即便仓位张数正确，也不能核算 USDT 金额是否正确。需补充本产品乘数/单位、成交及持仓价格口径、费用币种与费率来源、逐仓释放及盈亏结算公式、舍入时点，并明确按单笔还是累计结算。只阻塞金额预期，不能阻塞已知张数关系 |
| ISS-006 / 重要 | SRC-A 第 14 行，SRC-B 第 21 行：未明确部分成交后继续挂单、部分成交后撤单及撤单与成交竞争的状态/展示 | 需定义哪些最终成交已生效、未成交量如何撤销、终态如何区分，以及成交/订单/仓位/资金如何关联。同一已发生的成交不应因查询列表切换丢失，但准确状态名及取消规则需产品确认。阻塞上述终态与展示分支，主例可继续 |
| ISS-007 / 重要 | SRC-A 第 12 行，SRC-B 第 19 行：新参数的旧协议及在途适用边界未写明 | 需确认省略参数、旧普通限价单、发布前已挂单如何适用，避免无意改变非本次委托；仅核对实际会触达的范围。阻塞兼容分支，不自动扩展至新产品/模式 |

优先确认 ISS-001 和 ISS-002 的目标执行规则、ISS-005 的金额公式，再落实 ISS-003/004 的可观察性与恢复方案。建议由产品/风控决定交易语义，研发给出实现保证与证据接口；没有资料指明实际负责人。

## 5. 建议补充条款（均为建议稿，待确认）

- 对应 ISS-001：只减仓标记在订单生命周期中应保持可识别；在每次可能形成成交的业务裁决点，以项目定义的有效仓位及其他减仓占用判断可执行数量。无论采用何种分配和超额策略，都应满足 RUL-002。请在条款中选定超额部分的处理、剩余量、终态及释放规则，并说明其他平仓入口先发生、交错发生、仓位归零时的行为。此建议不指定执行算法。
- 对应 ISS-002：列出当前范围的输入约束与非法输入结果。若选用拒绝方案，要求拒绝不产生订单成交、仓位变化或不应有的资金占用；允许的业务订单记录及审计记录另行明确。错误码、张数步长及是否允许分数张均待项目确认。
- 对应 ISS-003/004：补充“受理但响应未知 → 按原业务标识查询 → 依据终态决定后续动作”的流程；定义订单与成交事件的稳定标识、去重作用域和生命周期。分别说明仓位和账务处理已提交后重试、进程重启、单边完成时的恢复结果，避免重复业务副作用。完成状态与收敛时限待确认。
- 对应 ISS-005：以本产品正式公式及配置版本定义成交量、费用、盈亏和保证金释放；写清张、乘数、USDT、价格与费率单位及每步舍入。没有这些来源前，不以任何平台的常见公式或默认费率替代。
- 对应 ISS-006/007：补充订单状态、列表和事件的对应关系，以及规则生效对象/时点、旧客户端与存量订单的解释。具体状态枚举与字段只在接口资料提供后固定。

## 6. 关键验收依据与交接

以下是少量关键依据，不是完整测试用例。金额计算应使用 Decimal 或整数最小单位；当前可计算的 5−2=3 直接使用整数张数。

| ID / 关联 | 前提与动作或事件 | 可观察结果、核对来源与限制 |
|---|---|---|
| AC-001 / RUL-003、004 | 初始多仓 5 张，记录仓位快照；有效只减仓单成交 2 张且没有其他仓位事件 | 关联该订单的实际成交累计为 2 张，最终仓位为多仓 3 张；订单/成交记录按 SRC-A 展示。用初始快照加成交明细核对数量，不能只看仓位接口自报成功。订单/成交关联字段、账务收敛观察点仍需提供；不据此断言费用和释放金额 |
| AC-002 / RUL-002、ISS-001 | 分别考察小于、等于、大于最终定义可平量的请求，以及多笔只减仓委托竞争同一仓位；可用合成初始 5 张、两笔各 3 张说明超额竞争 | 确定目标是该委托的实际执行不得让原方向跨零形成反向仓位；候选中的受理、裁剪、取消、剩余量及各订单终态依赖 ISS-001/002 决策，暂不能固定。核对受控事件顺序下的成交累计与仓位变化，需可观测/可控制裁决点；这不是已具备的环境能力 |
| AC-003 / RUL-002、ISS-001、006 | 一个只减仓委托已部分成交，之后另一已存在平仓入口先减少或清空仓位，或撤单与后续成交竞争 | 按最终确认的事件次序核对已发生成交、未成交量及订单终态，不反向目标始终适用。超出剩余仓位部分的处理、释放、列表位置和终态由 ISS-001/006 决定；不能提前断言一律自动撤销 |
| AC-004 / ISS-003、004 | 分别模拟提交生效但响应丢失、同一成交重复/乱序投递、仓位或账务消费者单边完成后重启 | 以稳定业务标识核对是否只形成应有订单和实际成交，以及每笔业务对仓位/账务的副作用次数。选择幂等方案和恢复语义后应避免重复业务；当前尚不能给出精确重试响应和恢复时限。需订单、成交、处理状态与资金流水的关联证据；HTTP 次数、重复通知条数和同源查询相等都不是独立结论 |
| AC-005 / ISS-005、004 | 固定初始仓位/资金快照、实际成交、公式及配置版本，处理到项目定义的账务完成截面 | 按确认公式独立核算 USDT 费用、盈亏及逐仓保证金变化，再与关联流水和余额变化核对。当前缺乘数、公式和精度，不能给出数字预期；不宣称所有余额简单相加守恒，不把被测余额返回当作其自身正确的证明 |
| AC-006 / RUL-005、ISS-002 | 无仓位时检查页面，并绕过页面向实际订单入口提交（仅是后续验证设计，不在本次执行） | 页面禁用来自已知资料；服务端不能因该委托成交形成仓位来自 RUL-002。响应、订单记录及资金占用预期待 ISS-002 决策，使用前后业务快照与成交/流水核对拒绝副作用 |

建议后续用模型/单元层验证仓位数量不变量和最终确认的可平分配；服务/接口层验证参数、幂等和两消费者恢复；必要的端到端层核对展示及跨查询收敛。分层建议不表示接口、事件注入、时间控制或流水读取能力已存在。当前不生成脚本、完整用例，不写入平台，也未执行任何交易。
