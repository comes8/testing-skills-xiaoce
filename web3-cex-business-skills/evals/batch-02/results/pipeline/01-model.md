# B2-01 部分成交后撤单：业务链路、状态与数量资金模型

本模型仅用于合成规则的文本设计，未执行交易、查询或平台操作。范围为普通现货限价买单，基础资产 A、报价资产 Q，限价单位 Q/A；不引入合约仓位、链上阶段、改单或成交更正。

## 2. 规则与对象

| 编号 | 规则或结论 | 证据性质 |
|---|---|---|
| RUL-201 | 数量至少 0.01 A，且是 0.01 A 的合法步长；非法数量直接拒绝，不取整。最大量与其他权限仍须满足，但值未知。 | 明示，SRC-201 |
| RUL-202 | 下单冻结 `L × q0` Q；每笔实际成交消耗 `pi × qi` Q，立即释放该笔价差；手续费为 0。 | 明示，SRC-201 |
| RUL-203 | `accepted=true` 仅为接收；实际撤单生效前仍可能成交，生效时剩余量停止撮合。 | 明示，SRC-202 |
| RUL-204 | 有剩余量且撤单实际生效：订单为 `CANCELED`；此前真实成交不得减少。剩余量先全部成交：订单为 `FILLED`，不得再标为取消。 | 明示，SRC-202 |
| RUL-205 | `CANCELED` 可与资金 `PENDING` 并存；也不要求必须经历可见的 PENDING。从实际取消生效起 2 秒内应为 `SETTLED`，该订单剩余冻结为 0。 | 明示与直接推导，SRC-202 |
| RUL-206 | 同一结算事件重复通知不得重复释放资金；通知条数不是成交或流水笔数。 | 明示，SRC-202 |
| RUL-207 | 查询与 WebSocket 来自同一订单读模型；相同展示不能独立证明账务正确。 | 明示，SRC-202 |

相关对象为：订单（orderId）、真实成交（executionId）、结算事件（settlementEventId）、Q 可用与订单归属冻结、资金流水、订单读模型。A 侧仅记录本订单成交取得量的增量，初始 A 未给，不能计算绝对余额；不存在本需求的衍生品仓位状态。来源已给关联标识，但没有证明可读取相应通道。[SRC-201、SRC-202、SRC-203]

## 3. 链路及生效位置

| 节点 | 触发、前置与动作 | 业务效果、后继与观察 |
|---|---|---|
| MOD-201 数量校验与下单 | 用户提交普通限价买单；先满足数量域及未给出的既有准入规则 | 数量非法则拒绝，不应形成可撮合订单或该订单资金冻结（由直接拒绝推导；合法审计记录不受排除）。通过后按 RUL-202 冻结。实际校验/冻结事务边界未知。 |
| MOD-202 实际成交 | 订单仍可撮合，发生真实 executionId | 按真实价量累计成交、消费 Q、立即释放价差；部分成交继续活动，全部成交转 FILLED。不是按通知条数累加。 |
| MOD-203 接收撤单 | 用户对尚有剩余量的订单请求撤单，收到 accepted=true | 仅确认接收；不能据此宣布 CANCELED、资金释放或 SLA 起算。继续观察实际成交/取消事件。失败响应与撤单重试协议未给。 |
| MOD-204 撤单生效 | 仲裁上撤单先于剩余量完全成交，且尚有活动剩余 | 终止剩余量撮合，活动剩余归零，保留累计成交，进入 CANCELED；进入独立的取消资金处理。实际仲裁记录通道未知。 |
| MOD-205 取消资金完成 | 订单已经实际取消；处理可暂未完成 | 可为 PENDING，最终应在规定期限内 SETTLED、本订单冻结为零。重复同一 settlementEventId 的通知不能再次释放。资金处理中间读数与原子边界未给。 |
| MOD-206 下游展示和核对 | 订单读模型更新、相关结果可读取 | 查询/WS 仅为展示观察；独立核对真实成交、取消/结算时刻和资金效果分别需要相应证据，不承诺展示同步时限。 |

以上跨对象节点不表示一个原子事务。数量拒绝无上述业务副作用是拒绝含义的推导，不扩展为“无任何写入”。[RUL-201～207；SRC-203]

## 4. 独立状态与必要顺序

除 `CANCELED`、`FILLED`、`PENDING`、`SETTLED` 与 `accepted=true` 外，以下中文状态都是逻辑描述，非新增平台枚举。

| 对象及原状态 | 事件/守卫 | 目标状态与效果 | 观察及来源 |
|---|---|---|---|
| 订单：未建立 | 数量非法 | 拒绝；不进入本订单撮合/冻结链路 | 校验结果、订单及冻结副作用；RUL-201 |
| 订单：活动、已有部分成交 | 撤单已接收，但尚未实际生效 | 不由受理事件单独确定终态；有效成交仍可能增加 | 接收与业务生效证据分离；RUL-203 |
| 订单：活动 | 撤单生效前再发生部分成交，累计仍小于原量 | 累计成交增加，仍有剩余；此后若取消生效则 CANCELED | executionId、真实顺序；RUL-202～204 |
| 订单：活动 | 剩余量在撤单生效前全部成交 | FILLED；不再转 CANCELED | 真实成交与仲裁证据；RUL-204 |
| 订单：活动且有剩余 | 撤单实际生效 | CANCELED；活动剩余为 0，未成交量归已取消量 | 实际取消事件；RUL-204、INV-201 |
| 订单：CANCELED | 取消之后新的撮合执行企图 | 不允许产生归属于取消后剩余量的新真实成交；此前成交的迟到通知不算新执行 | 实际业务先后，不能用通知到达顺序代替；RUL-203、204 |
| 取消资金：未完成 | 取消已经生效，资金尚未完成 | PENDING 与 CANCELED 合法并存；不能强求此时冻结已为 0 | 资金状态及同截面账户证据；RUL-205 |
| 取消资金：未完成/PENDING | 实际结算完成 | SETTLED 且本订单冻结为 0；也允许取消即完成而没有可见中间态 | settledAt 与真实资金效果；RUL-205 |
| 取消资金：已处理 | 同一结算事件重复通知 | 不得产生重复释放效果；不规定日志或流水行数 | settlementEventId 与资金效果；RUL-206 |
| 成交/展示 | 重复或迟到通知/展示更新 | 通知本身不改变真实成交事实；没有材料定义的独立推送状态枚举或展示 SLA | executionId 与来源独立性；RUL-206、207 |

竞争共享资源是同一 orderId 的剩余可执行量。三条必要路径：

1. **取消先**：取消实际生效 → 阻止其后剩余量执行 → CANCELED。
2. **额外部分成交先**：额外执行 → 仍有剩余 → 取消生效 → CANCELED，按实际累计成交重算已取消量及资金。
3. **剩余全部成交先**：真实成交使累计达到原量 → FILLED，不能再取消该订单。

三条是依据实际先后分别固定的分支，不能对同一已知顺序任选终态。确切同时的内部仲裁策略、锁和读取通道均未给，不虚构。结算通知迟到或重复也不倒置真实成交/取消顺序。[RUL-203～206；ISS-R02、ISS-E02]

## 5. 数量与资金关系

### 5.1 变量、截面与不变量

数量均以 A 计：q0 为原始量，f 为按真实执行去重归因的累计成交，u 为 unfilledQty，a 为 activeQty，c 为 cancelledQty。它们是合成逻辑口径，无改单或成交更正；比较必须使用同一订单、同一业务截面。[SRC-201]

- **INV-201（推导）**：`u = q0 − f`，`q0 = f + a + c`，且各数量非负。活动且未取消时 `c=0，a=u`；取消后 `a=0，c=u`；FILLED 时 `f=q0，a=c=u=0`。取消不能把 u 也清零。
- **INV-202（明示/推导）**：无成交更正时 f 不因取消或重复通知下降；取消实际生效后不得新增其剩余量的真实成交。[RUL-203、204、206]
- **INV-203（明示/推导）**：FILLED 与 CANCELED 的分支由实际生效顺序决定；受理不决定终态。[RUL-203、204]

资金：L 为限价（Q/A），每笔真实成交为 `(qi A, pi Q/A)`，实际消费 `C=Σ(pi×qi)` Q，费用为 0。没有其他资金/订单事件，且不是取消资金处理中间态时，活动阶段本订单冻结 `F=L×a`；下单冻结 `L×q0`。每笔成交的冻结消耗口径为 `L×qi`，其中 `pi×qi` 用于成交，`(L−pi)×qi` 立即释放回可用。[RUL-202，推导]

- **INV-204（推导）**：可完整核对的下单/逐笔成交资金截面，`可用Q = 初始可用Q − L×q0 + Σ((L−pi)×qi)`；本例初始冻结为 0。取消结算全部完成后，本订单最终冻结为 0、`最终可用Q = 1000 − C`。这只适用于本样例已排除其他资金/订单事件的 Q 账户关系，不是“所有资产总和守恒”。
- **INV-205（明示）**：对实际取消，`0 ≤ settledAt − cancelEffectiveAt ≤ 2 秒`，二者为同一服务时钟的实际事件时刻；终点还须满足 SETTLED 及本订单 F=0。等于 2 秒满足“2 秒内”。首次轮询终态时间不是该差值。[RUL-205]
- **INV-206（明示/推导）**：同一 settlementEventId 重复通知不得增加取消释放的总资金效果；不限制通知、审计或多行记账的数量。[RUL-206]

SRC-201 的 `F=L×activeQty` 不能跨取消处理中间态机械套用：SRC-202 允许订单已取消但资金尚 PENDING。该阶段 a 已为 0，不足以证明 F 已为 0；具体中间资金值与可用/冻结同步原子性未明。上式限定在完整资金截面，未自行规定 PENDING 必须固定保留或一次释放全部冻结。[RUL-202、205；ISS-R01]

精度：数量域按 0.01 A；价格精度、Q 最小单位和通用舍入规则未提供。下述固定数值均可用十进制精确表达，无须假设舍入；推广至需舍入数据时须补充规则，不默认费率或精度。[SRC-201、SRC-203]

### 5.2 固定样例：取消期间没有其他成交或资金事件

| 业务截面 | f / u / a / c（A） | 可用 Q | 该订单冻结 Q | 独立推导 |
|---|---:|---:|---:|---|
| 初始 | 尚无本订单 | 1000 | 0 | SRC-201 给定 |
| 限价 10、原量 5 已冻结 | 0 / 5 / 5 / 0 | 950 | 50 | 冻结 10×5=50 |
| 真实成交 2@9.5 后，取消尚未生效 | 2 / 3 / 3 / 0 | 951 | 30 | 消费 19；本笔冻结减少 20，其中价差 1 立即释放 |
| 取消已实际生效、资金未必完成 | 2 / 3 / 0 / 3 | 中间值未固定 | 不据 a=0 强判为 0 | 订单 CANCELED；资金可 PENDING，也可能已经 SETTLED |
| 取消资金 SETTLED | 2 / 3 / 0 / 3 | 981 | 0 | 再释放剩余 30；1000−19=981；相对下单后释放合计 31，不能把 31 全记成取消释放 |

本订单取得 A 的成交增量为 2 A，未给初始 A，故不写绝对余额。也不将 2 A 与 981 Q 直接相加。[SRC-201；INV-201、204]

反例用于检查模型的独立约束：`f=2,u=0,a=0,c=3` 只破坏未成交量口径；取消后 `f=1` 破坏已成交保留；固定样例最终可用 980 说明价差少释放 1，1011 说明多释放取消余款 30；`CANCELED+PENDING` 本身不是错误；`CANCELED+SETTLED+F=30` 是错误。[INV-201～206]
