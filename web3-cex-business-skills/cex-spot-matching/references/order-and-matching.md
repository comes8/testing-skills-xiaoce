# 订单与撮合维度

## 规则画像

按当前产品资料核对市场阶段、资产单位、价量/金额精度、价格带、账户/交易对限制、订单类型、有效期、撮合资格、优先级、成交价、自成交策略与费用版本。信息缺失只阻塞相关预期，不自行填行业默认。

来源明确的规则、逻辑推导、实际读到的实现与待确认建议分开。撮合接收顺序、事件生效顺序和外部请求先后不可互换。

## 业务场景矩阵

| 维度 | 需要区分的场景和判据 |
|---|---|
| 价格优先与同价顺序 | 多价位跨档、同价不同有效时间、部分成交后余量排队；排序规则与时间来源以项目为准 |
| 成交价 | 挂单价、主动单价格或其他规则的适用前提；跨档逐笔价量与加权均价，不能只核对总成交量 |
| 流动性资格 | 自成交防护、特殊订单/账户或不可见流动性是否参与可成交判断；先资格再计算可用量 |
| 限价与市价 | 买卖方向、基础量/报价额、价格保护、流动性不足、尾差、费用占用与剩余处理 |
| 有效期 | IOC 部成后余量、FOK 成交资格检查与提交窗口、Post Only 可能成交时的处理、项目支持的到期方式 |
| 撤单 | 成交先、撤单先、处理中又部分成交、全成后取消请求；保留真实成交，不依响应先后来定生效顺序 |
| 改单 | 增减原量、不得低于已成量的具体语义、价格变化、换号、优先级、冻结和并发；各策略需来源 |
| 自成交防护 | 同属主体的定义、主动/被动规则优先级、取消/减量行为、是否继续找下一对手、受影响数量和冻结 |
| 边界与拒绝 | 精度、最小数量/金额、价格带、余额、交易状态、账户归属；隔离不同拒绝原因，不造错误码 |
| 事件与恢复 | 已生效响应丢失、重复命令/通知、快照重放、主备切换后的结果与副作用；不假定 exactly-once |

每个关键机制选择能推翻错误实现的数据。总量足够并不说明按资格或保护价过滤后的流动性足够；FOK 的一致性判断应与真实执行使用的资格和时点对齐。如何保证原子性是研发核对点，不能擅定锁或事务架构。

## 独立撮合轨迹

固定初始逐单簿和输入序列，记录每一笔：主动单、对手、资格判断、价格、成交量、双方累计/活动余量及下一个候选。规则改变时标注生效位置，不用最终快照倒推唯一事件序列。

量关系需固定是否发生改单、替换、撤回或成交更正。一个价位的总量对得上，仍可能存在对手或同价优先级错误；若只有聚合行情，明确证明能力不足。

撮合、订单存储、资金结算和行情生产分别给效果与收敛关系。中间态合法性取决于资料，不能因为最终一致就放过明确的生效后新增成交或重复结算。
