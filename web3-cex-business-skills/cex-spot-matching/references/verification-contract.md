# 验证与输出

输出按任务选择规则缺口、撮合轨迹、业务测试点或已有点的评审，不强制同时生成多份重复报告。核心信息：

- 产品、资产单位、规则版本和实际输入/来源位置；保留 SRC/RUL/ISS/TP 等既有编号。
- 控制初态、逐事件顺序、对手资格、成交价量、订单及簿变化。
- 资金衔接的已知公式、费用、精度与事件截面；未定部分标问题。
- 每个测试点的目标、条件、预期、核对方法、风险理由和准备能力。
- 不适用范围、未覆盖机制及哪些结论暂不能证明。

## 独立计算与证据

逐笔成交价量计算消费、收入、加权价格及费用；按费用币种分别记，按来源选择逐笔或累计舍入。不能用主动单限价替代实际成交价，也不默认取消退回已消费金额。

冻结、价差释放和取消释放不可重复计为收入。区分完成前提和处理中；来源公式阶段不明时提出问题，不能擅自缩限。所有数值用 Decimal 或整数最小单位，示例只限指定前提。

示例数值恰为整数，只说明该算术没有小数尾差，不代表资料已定义账务最小单位为1。价格步长、数量步长和资产记账精度是不同维度；数值推导可继续，存储精度/舍入边界的预期仍需相应来源。

重复消息可以归组追踪；全部真实成交、记账和余额效果应保留，不能先按相同 ID 删除重复执行证据。多行合法记账要按账户/科目语义解释，不能直接按行数判重复。

## 场景与缺口

复合目标的独立约束分别可判定。竞争分支按实际生效先后拆开；一个 TP 下多个变体给子标签，逐变体留证。给优先级建议时说明本次风险，不把全表标最高级。

超额、STP、FOK/IOC、改单优先级等规则未定时，列受阻子断言，不把所有可能结果都放进“任选即过”。缺少逐单簿、仲裁或独立流水读取是执行准备问题，不改写已明确业务规则。

增量保留原 ID，重复 ID 按原位置定位并给显式映射。引用必须存在，不用未定义缩写。无需依赖其他 Skill 或具体平台；完整用例、平台格式适配和执行由后续任务处理。
