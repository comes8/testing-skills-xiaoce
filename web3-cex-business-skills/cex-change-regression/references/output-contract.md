# 影响分析与回归交付

默认中文报告与表格，用户指定格式则采用其格式；信息语义不等于任何平台的直接导入Schema。

## 影响分析

记录比较基线、来源/版本、行为差异、直接与关联因果链、存量与兼容、证据性质/边界、未决问题。沿用既有SRC/REQ/RUL/ISS/TP/TC编号，可按需新增CHG和IMP；不强造所有表。

没有代码时输出需核对的实现影响，不写成已观察事实。没有新旧资料时说明比较不完整，仍交有依据的部分。

## 回归选择

| 字段 | 说明 |
|---|---|
| 资产与处置 | 原TC/新增ID、复用/修订/新增/受阻/不选，保留原版本 |
| 理由与关联 | 变更/影响链、来源、业务后果和需验证性质 |
| 条件与版本 | 产品/模式、数据、创建/执行/记账等版本截面 |
| 范围和优先级 | 必测/关联/兼容恢复/暂缓/不选及风险理由 |
| 顺序与成本 | 有来源的估计、依赖/资源与预算；未知不填0 |
| 状态与证据 | 规则待决、执行准备、真实结果分别记录，给需保留的证据 |

只要求范围时不展开详细步骤用例。只评局部变更不能宣称整个交易所已完成回归。

## 计划与真实结果分开

计划中的必测、已准备和可执行不等于已经通过。历史通过注明原版本/环境/数据/运行，只能支持那次执行；新版无证据时是未执行，无法执行时说明阻塞。

若提供了真实结果，按同一范围、版本与统计口径分列通过、失败、阻塞和未执行。缺少分母或映射不算覆盖率，不把预算内先行集当完整必测集合。

## 结论

说明已分析的影响、必要范围、预算/能力下能先做什么，以及剩余必测、未决事项与风险。可提出发布前应满足的项目条件，但没有审批授权和运行证据时不能作发版批准。

不实际部署、回滚、跑自动化、写平台或创建发布记录，也不把普通报告声称为已导入资产。该Skill不依赖其余规划技能，可直接消费用户给定资料与用例。
