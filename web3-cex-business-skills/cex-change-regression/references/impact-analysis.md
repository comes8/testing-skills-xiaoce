# 变更影响追溯

## 比较什么

固定旧/新来源版本与适用范围，不用文件修改时间冒充业务生效时间。记录新增、修改、删除、不变和待确认的行为。

| 变更维度 | 需要追踪的关系 |
|---|---|
| 公式、精度与费用 | 调用者、默认参数、逐笔/累计、币种、舍入、持久化与下游重复计算 |
| 状态/时点 | 校验与执行、受理/终态/结算、创建版本、资格快照、在途与旧对象 |
| 参数/协议/事件 | 生产者、消费者、旧字段、缺字段、未知字段、版本默认和回放 |
| 共享实现 | 实际调用链和可达条件，不因入口或路径不变排除；不同调用者的规则可能不同 |
| 数据/存储 | 历史记录、读模型、索引/缓存、重算、修正及审计，而不只看表结构有无改变 |
| 配置与发布 | 生效时点、灰度组合、版本固化、旧代码对新对象的处理及回滚边界 |
| 权限与账户模式 | 账户归属、产品能力、限额/风险门槛，对相关模式按因果关系选择 |

## 影响边的证据

边可来自已确认架构、提供的代码/差异、实际读取的调用关系或运行证据。写清“材料明示/实现观察/待核对”；一份拟议差异不等于已上线实现，未扫描完整依赖不能声称没有其他调用者。

输出因果链，例如“默认舍入策略改变 → 共享计算函数未显式传版本的调用者 → 结算费用变化 → 账务/权益”。如果字段新增但API URL不变，仍检查事件兼容与读写方。

缺少依赖图时分析已知直接风险并列待核对边，不假造模块；不能把未知变成确定不影响。项目明确独立路径且配置未改时，可以说明为何本轮不选，并保留该证据的适用范围。

## 业务版本与存量对象

明确创建、成交、触发、记账和展示使用哪个版本。旧订单跨新配置、同一订单多次成交、历史已记费用、消息晚到或重放都可能使用不同基线，不能简单取“当前最新”重算。

新旧节点并存时确认它们是否理解对方产生的规则标识与字段。回滚配置不必意味着可以回滚所有已建对象；旧二进制能否处理新版本规则是独立能力问题。

## 原始目标与实现风险

需求说某业务规则不改，但共享默认值可能改变该业务时，记录“关联影响待核对/存在变更风险”，不能只按需求标题排除，也不能没有运行证据就说已复现缺陷。

将经济效果、完整记账与查询展示分别追溯。单个展示未变或最终净额相同，不证明所有上游语义未变；重复扣款也不能按事件ID先删去再比较。
